# Контракты REST API

Документ описывает HTTP-контракты backend, реализованные в исходном коде проекта. Базовый адрес при локальном запуске: `http://localhost:3000/api`. Идентификаторы в примерах условные. Все даты передаются как календарные даты `YYYY-MM-DD`.

## Общие правила

- Защищённые маршруты требуют cookie `rfm_access_token`, которую устанавливают `/auth/register` и `/auth/login`. Cookie имеет флаги `HttpOnly`, `SameSite=Strict`, `Path=/`; в production также `Secure`. Передавать JWT в теле ответа не требуется и не следует.
- Все данные клиентов, транзакций, анализов и сегментов ограничены аккаунтом из авторизационной cookie. Чужой или отсутствующий анализ отвечает `404`, чтобы не раскрывать его наличие.
- API принимает JSON для запросов с телом, кроме загрузки файлов, которая использует `multipart/form-data` с единственным полем `file`.
- Параметры DTO проходят глобальную проверку. Неизвестные свойства JSON отклоняются. Ошибка имеет вид:

```json
{
  "statusCode": 400,
  "message": "Импорт отменён: исправьте некорректные строки.",
  "errors": ["Строка 2: некорректная дата покупки"],
  "requestId": "<идентификатор запроса>",
  "timestamp": "2026-11-01T12:00:00.000Z",
  "path": "/api/data/import/csv"
}
```

- Неожиданная ошибка сервера возвращает `500` с безопасным общим сообщением и `requestId`; детали запроса и SQL не включаются в ответ. Ответы также содержат заголовок `X-Request-Id`.
- `401` — отсутствует/недействительна сессия; `400` — неверные поля, фильтры или импорт; `404` — объект недоступен текущему аккаунту; `413` — файл больше 10 МБ; `429` — превышен лимит запросов; `500` — внутренняя ошибка.

## Аутентификация и профиль

| Метод и путь | Доступ | Запрос | Успешный ответ |
|---|---|---|---|
| `POST /auth/register` | публичный; до 5 запросов в час | JSON `{ "email": "user@example.com", "password": "не менее 8 символов", "fullName": "Имя" }`. Имя: непустое, до 200 символов; пароль: 8–72 символа; email: до 254 символов. | `201` и `{ "user": { "id", "email", "fullName", "role" } }`; создаёт HttpOnly-cookie. |
| `POST /auth/login` | публичный; до 10 запросов за 15 минут | JSON `{ "email": "user@example.com", "password": "…" }` | `201` и публичный профиль в поле `user`; создаёт cookie. При неверной паре — `401`. |
| `POST /auth/logout` | публичный | без тела | `204`; удаляет cookie. |
| `GET /auth/profile` | авторизованный | без параметров | Публичный профиль текущей сессии. |
| `GET /users/profile` | авторизованный | без параметров | Публичный профиль текущего аккаунта. |

## Импорт и данные

Все маршруты этого раздела требуют авторизации. Для четырёх маршрутов импорта действует лимит 20 запросов в час на пользователя. Файл должен быть не больше 10 МБ; предел строк — 50 000. До записи используйте соответствующий маршрут `preview`.

| Метод и путь | Запрос и результат |
|---|---|
| `POST /data/import/csv/preview` | `multipart/form-data`, поле `file`, расширение `.csv`. Читает UTF-8, UTF-16 BOM и Windows-1251; определяет разделитель запятая/точка с запятой/табуляция. Возвращает `clientsInFile`, `transactionsInFile`, `dateFrom`, `dateTo`, до 10 `sampleRows`. Не сохраняет данные. |
| `POST /data/import/csv` | То же поле и формат. После успешной проверки сохраняет строки в транзакции БД; ответ `{ "clientsImported": число, "transactionsImported": число, "errors": 0 }`. Повторный внешний ID клиента внутри аккаунта связывает покупки с существующим клиентом. |
| `POST /data/import/excel/preview` | `multipart/form-data`, поле `file`, расширение `.xlsx` или `.xls`; читается первый лист книги. Формат результата и отсутствие записи соответствуют CSV preview. |
| `POST /data/import/excel` | То же поле и формат; сохраняет проверенные записи и возвращает счётчики импорта. |
| `GET /data/clients` | Параметры `page` (по умолчанию 1), `pageSize` (25, диапазон 1–100), `search` (до 100 символов; имя, внешний ID, email). Возвращает `{ items, page, pageSize, total, totalPages }`. |
| `GET /data/transactions` | `page`, `pageSize`, `search`, `clientId`, `dateFrom`, `dateTo`. Диапазон дат включительный; даты `YYYY-MM-DD`; начало не позже конца. Поиск по имени/внешнему ID клиента. Ответ с пагинацией `{ items, page, pageSize, total, totalPages }`. |
| `GET /data/stats` | Без параметров. Возвращает `totalClients`, `totalTransactions`, `totalRevenue` для текущего аккаунта. |
| `GET /health` | Публичная проверка API и БД: `200` и `{ status: "ok", components: { api: "ok", database: "ok" }, checkedAt }`; при недоступной БД — `503` и `database: "unavailable"`. |

Обязательные столбцы CSV/Excel: `client_id` (также `clientId`/`id`), `transaction_date` (также `transactionDate`/`date`), `amount` (также `sum`). Дополнительные: `full_name`/`fullName`/`name`, `email`, `phone`, `client_type`/`clientType`, `items_count`/`itemsCount`, `payment_method`/`paymentMethod`. Если количество товаров опущено, используется `1`. При ошибках строк импорт отменяется целиком; ответ содержит до 100 сообщений с номерами строк.

## RFM-анализ и история

| Метод и путь | Запрос и результат |
|---|---|
| `POST /rfm/analyze` | JSON `{ "startDate": "2026-01-01", "endDate": "2026-03-31", "quartilesCount": 5 }`. Период обязателен, даты действительны и начало не позже конца; число квантилей необязательно, целое от 3 до 10, по умолчанию 5. Нужна хотя бы одна транзакция; максимум 100 000 за период. Ответ включает `analysisConfigId`, конфигурацию анализа, `clientsAnalyzed`, `rfmScores`, `segments`, `interpretation`. |
| `GET /rfm/analyses` | `page` (1), `pageSize` (20, максимум 100), необязательные `periodStart`, `periodEnd`. Возвращает страницу `items` с конфигурациями, числом клиентов и статусом, а также `page`, `pageSize`, `total`, `totalPages`. Только анализы текущего пользователя. |
| `GET /rfm/results/:configId` | Возвращает `analysisConfig`, `rfmScores`, сводки `segments` и `interpretation` (может быть `null` для старого анализа, чьи данные нельзя безопасно сопоставить владельцу). Чужой/несуществующий ID: `404`. |
| `GET /rfm/results/:configId/clients` | Пагинация `page` (1), `pageSize` (25, диапазон 10–100); фильтры `search`, `segmentPattern`, `minR/maxR`, `minF/maxF`, `minM/maxM`. Оценки — целые от 1 до числа квантилей анализа; минимум не выше максимума. Возвращает страницу клиентских оценок и агрегаты для совпавшего набора. |
| `GET /rfm/results/:configId/clients/:clientId` | Детали клиента, его RFM-показатели и до 100 транзакций периода; содержит `transactionsTotal` и признак усечения `transactionsTruncated`. Доступен только владельцу анализа и клиента. |
| `GET /rfm/segments` | Сегменты, обнаруженные в последнем анализе текущего пользователя. |

RFM-оценки строятся по транзакциям только текущего аккаунта. Для Recency больший балл соответствует более недавней покупке; для Frequency и Monetary больший балл соответствует большему значению. Равные значения показателя получают общий ранг-квантиль.

## Справочник сегментов

| Метод и путь | Результат |
|---|---|
| `GET /segments` | Список сегментов последнего анализа текущего пользователя. Если анализов ещё нет, возвращает пустой список. |
| `GET /segments/stats` | Сводки последнего результата текущего аккаунта без списков клиентских оценок. |
| `GET /segments/:id` | Подробности сегмента, если он присутствует в доступных анализах пользователя; иначе `404`. |

## Внутренний сервис интеллектуальной интерпретации

Этот сервис вызывается backend-ом и не является маршрутом браузерного клиента. По умолчанию адрес `http://127.0.0.1:8001`; backend настраивает его переменной `AI_SERVICE_URL`. `GET /health` возвращает `200` и `{ "status": "ok" }`. `POST /interpret` принимает JSON `{ totalClients, quartilesCount, segments }`, где сегмент содержит `segmentName`, `rfmPattern`, `clientCount`, `avgMonetary`; успех возвращает `summary`, `insights[]`, `recommendations[]`. При сбое, превышении тайм-аута или некорректном ответе backend продолжает сохранять числовой RFM-результат и помечает интерпретацию как `unavailable`.

## Примеры

Запуск анализа после входа (cookie браузера должна быть включена):

```http
POST /api/rfm/analyze
Content-Type: application/json
Cookie: rfm_access_token=<HttpOnly-cookie браузера>

{"startDate":"2026-01-01","endDate":"2026-03-31","quartilesCount":5}
```

Загрузка CSV использует `multipart/form-data` и имя поля `file`; frontend предварительно вызывает `/api/data/import/csv/preview`, показывает результат и только после явного подтверждения вызывает `/api/data/import/csv`.
