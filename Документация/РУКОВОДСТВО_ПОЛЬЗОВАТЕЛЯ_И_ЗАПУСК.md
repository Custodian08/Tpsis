# Руководство пользователя и локальный запуск

Инструкция рассчитана на учебный запуск приложения в Windows. Она не является инструкцией по production-размещению: для внешней публикации отдельно настраиваются HTTPS, регулярные резервные копии, мониторинг и сетевые правила.

## 1. Требования

- Node.js 20 или новее и npm.
- PostgreSQL 16 или новее с созданной базой `rfm_analysis`.
- Три терминала PowerShell для frontend, backend и AI-service.
- Зависимости проекта (`npm install` в каталогах `backend`, `ai-service`, `frontend`).

## 2. Однократная настройка

1. Установить PostgreSQL и создать пустую базу `rfm_analysis`.
2. В pgAdmin Query Tool выполнить `backend/database/init.sql`.
3. Для уже существующей базы сравнить историю применённых миграций с `backend/database/README.md`. Не выполнять повторно инициализацию поверх рабочей схемы. Применять только пропущенные миграции 001–003 по порядку; перед изменениями существующей базы создать backup. Миграцию владения 004 выполнять командой `npm run db:migrate-ownership` из каталога `backend`: она создаёт backup и проверяет результат.
4. Скопировать `backend/.env.example` в `backend/.env`. Указать адрес и пароль PostgreSQL, базу `rfm_analysis`, `FRONTEND_URL=http://localhost:5173`, `AI_SERVICE_URL=http://127.0.0.1:8001` и локально сгенерированный `JWT_SECRET` длиной от 32 символов. Не публиковать `.env`.
5. Установить зависимости из корня каждого компонента:

```powershell
Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\backend'
npm install

Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\ai-service'
npm install

Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\frontend'
npm install
```

Замените `D:\ПУТЬ\К\ПРОЕКТУ` на реальный путь к папке проекта. Если база уже настроена, пункты с SQL повторно не выполняйте.

## 3. Запуск приложения

Откройте три отдельных окна PowerShell и в каждом запустите указанный процесс. Оставьте окна открытыми, пока пользуетесь приложением.

**Терминал 1 — backend:**

```powershell
Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\backend'
npm run start:dev
```

Проверка API: откройте `http://localhost:3000/api/health`. Готовность API и БД отображается статусом 200.

**Терминал 2 — сервис интерпретации:**

```powershell
Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\ai-service'
npm start
```

Проверка сервиса: `http://127.0.0.1:8001/health` должен вернуть `{"status":"ok"}`.

**Терминал 3 — интерфейс:**

```powershell
Set-Location -LiteralPath 'D:\ПУТЬ\К\ПРОЕКТУ\frontend'
npm run dev
```

В браузере откройте `http://localhost:5173/login`. Остановка каждого процесса — `Ctrl+C` в соответствующем окне. При повторном запуске достаточно снова открыть три терминала и выполнить команды.

## 4. Основной сценарий аналитика

1. **Регистрация или вход.** Создайте учётную запись на странице регистрации либо войдите. Пароль должен содержать не менее 8 символов. Сессия хранится в HttpOnly-cookie.
2. **Импорт.** Откройте раздел импорта и выберите CSV, XLS или XLSX. Сначала появится предпросмотр: число клиентов и транзакций, даты и примеры строк. Исправьте ошибки, если они есть. Проверьте сводку и подтвердите импорт отдельной кнопкой.
3. **Формат файла.** Обязательны столбцы `client_id`, `transaction_date`, `amount`. Дополнительно можно указать `full_name`, `email`, `phone`, `client_type`, `items_count`, `payment_method`. Примеры и псевдонимы заголовков описаны в корневом README и API-контрактах.
4. **Анализ.** Перейдите в RFM-анализ, задайте даты начала/окончания и число квантилей (3–10), затем запустите расчёт. В базу и результаты включаются только данные вашего аккаунта.
5. **Результаты и история.** В истории выберите запуск. Просмотрите карточки итогов, распределение сегментов и оценки. Используйте поиск клиента и фильтры R/F/M. Откройте клиента, чтобы увидеть показатели и транзакции, относящиеся к выбранному периоду.
6. **Визуализация и сегменты.** Выберите запуск; подсказки графиков показывают детали, нажатие на столбец или ячейку карты R×F открывает соответствующий список.
7. **Экспорт.** На странице экспорта выберите запуск и фильтры, просмотрите состав выгрузки и скачайте CSV или JSON. CSV подготовлен с UTF-8 BOM и `;` как разделителем. Перед использованием в отчёте проверьте открытие файла в своей версии Excel/LibreOffice.
8. **Выход.** Используйте кнопку выхода, чтобы закрыть сессию в браузере.

## 5. Если возникла ошибка

- Если `/api/health` не открывается, проверьте, что запущен backend и файл `.env` содержит корректные настройки PostgreSQL и JWT.
- Если `/health` сервиса интерпретации недоступен, перезапустите AI-service. Числовой RFM-результат может сохраниться без текстовых рекомендаций.
- Ошибка импорта указывает строку и причину. Исправьте файл и повторите предпросмотр; база меняется только после подтверждения успешно проверенного файла.
- Если окно браузера показывает старую версию, обновите страницу. После обновления приложения войдите заново.
- При ошибке API сохраните отображаемый `requestId`; он помогает сопоставить обращение с записью журнала сервера. Не отправляйте `.env`, пароль или содержимое cookie.

## 6. Ограничения и поддержка

- Один импорт ограничен 10 МБ и 50 000 строк; запрос анализа обрабатывает не более 100 000 транзакций.
- При повторной загрузке того же файла существующие карточки клиента в аккаунте переиспользуются по `client_id`, но транзакции файла импортируются повторно. Стабильного идентификатора транзакции в текущем шаблоне нет.
- Отрицательная сумма уменьшает Monetary и может представлять возврат; отдельный статус отмены/возврата пока не поддерживается. Перед бизнес-решениями проверьте исходные данные и период.
- Текстовая интерпретация — набор экспертных правил, не прогноз оттока и не замена проверки аналитика.
- Автоматизированный протокол и расширенные контракты API находятся в этой же папке: `TEST_PLAN_AND_REPORT.md`, `API_CONTRACTS.md`.
