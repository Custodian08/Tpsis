ОПИСАНИЕ ПРЕДМЕТНОЙ ОБЛАСТИ

1. Определение границ предметной области

Предметная область данного проекта охватывает процессы анализа клиентской базы с использованием метода RFM-анализа (Recency, Frequency, Monetary) и визуализации полученных результатов. Система предназначена для помощи компаниям в сегментации клиентов, выявлении ключевых групп покупателей и принятии обоснованных маркетинговых решений.

Входит в рамки предметной области:

  • Импорт данных о клиентах и их транзакциях из внешних источников (CSV, Excel, базы данных);
  • Обработка и очистка входных данных;
  • Расчет RFM-метрик для каждого клиента;
  • Сегментация клиентов на основе RFM-показателей;
  • Интерактивная визуализация результатов анализа (графики, диаграммы, таблицы);
  • Экспорт результатов анализа в различные форматы;
  • Сохранение и загрузка конфигураций анализа;
  • Генерация отчетов по результатам сегментации.

Не входит в рамки предметной области:

  • Сбор первичных данных о клиентах (система работает с уже существующими данными);
  • Автоматическая отправка маркетинговых коммуникаций клиентам;
  • Интеграция с CRM-системами в реальном времени;
  • Предиктивное моделирование поведения клиентов;
  • Управление лояльностными программами;
  • Финансовые транзакции и платежные операции.

2. Словарь терминов (Глоссарий)

Термин Определение
RFM-анализ Метод сегментации клиентов по трем критериям: Recency (давность последней покупки), Frequency (частота покупок), Monetary (денежная ценность клиента)
Recency (R) Количество дней, прошедших с последней покупки клиента. Чем меньше значение, тем выше активность клиента
Frequency (F) Количество покупок, совершенных клиентом за определенный период. Чем выше значение, тем лояльнее клиент
Monetary (M) Общая сумма денег, потраченная клиентом за определенный период. Чем выше значение, тем ценнее клиент для компании
Сегмент клиентов Группа клиентов с похожими характеристиками и поведением, выделенная на основе RFM-анализа
Квантиль Значение, которое делит упорядоченный набор данных на равные части. В RFM-анализе используется для ранжирования клиентов по каждому показателю
RFM-оценка Числовое значение, присваиваемое каждому клиенту по каждому критерию (обычно от 1 до 5), отражающее его относительную позицию среди всех клиентов
Клиентская база Совокупность данных о клиентах компании, включая их демографические характеристики, историю покупок и взаимодействия с компанией
Транзакция Запись о покупке, совершенной клиентом, содержащая информацию о дате, сумме и приобретенных товарах/услугах
Сегментация Процесс разделения клиентской базы на однородные группы на основе общих характеристик или поведения
Дашборд Интерактивная панель визуализации, отображающая ключевые показатели и результаты анализа в виде графиков, диаграмм и таблиц

4. Бизнес-сущности и их взаимосвязи

Сущность: Клиент

Описание: Физическое или юридическое лицо, совершавшее покупки в компании.

Атрибуты:

  • client_id – уникальный идентификатор клиента (целое число)
  • full_name – полное имя клиента (строка)
  • email – электронная почта (строка)
  • phone – номер телефона (строка)
  • registration_date – дата регистрации клиента (дата)
  • client_type – тип клиента (физическое/юридическое лицо) (строка)

Сущность: Транзакция

Описание: Запись о покупке, совершенной клиентом.

Атрибуты:

  • transaction_id – уникальный идентификатор транзакции (целое число)
  • client_id – идентификатор клиента (целое число, внешний ключ)
  • transaction_date – дата совершения покупки (дата)
  • amount – сумма покупки (вещественное число)
  • items_count – количество товаров в покупке (целое число)
  • payment_method – способ оплаты (строка)

Сущность: RFM-оценка

Описание: Рассчитанные RFM-метрики для конкретного клиента.

Атрибуты:

  • rfm_id – уникальный идентификатор записи (целое число)
  • client_id – идентификатор клиента (целое число, внешний ключ)
  • recency_days – количество дней с последней покупки (целое число)
  • frequency_count – количество покупок за период (целое число)
  • monetary_value – общая сумма покупок за период (вещественное число)
  • r_score – оценка по критерию Recency (целое число, 1-5)
  • f_score – оценка по критерию Frequency (целое число, 1-5)
  • m_score – оценка по критерию Monetary (целое число, 1-5)
  • rfm_segment – сегмент клиента (строка)
  • analysis_date – дата проведения анализа (дата)

Сущность: Сегмент

Описание: Группа клиентов с определенным RFM-профилем.

Атрибуты:

  • segment_id – уникальный идентификатор сегмента (целое число)
  • segment_name – название сегмента (строка)
  • rfm_pattern – RFM-паттерн сегмента (строка, например "555")
  • description – описание сегмента (строка)
  • client_count – количество клиентов в сегменте (целое число)
  • avg_monetary – средняя ценность клиента в сегменте (вещественное число)

Сущность: Конфигурация анализа

Описание: Настройки параметров RFM-анализа.

Атрибуты:

  • config_id – уникальный идентификатор конфигурации (целое число)
  • config_name – название конфигурации (строка)
  • analysis_period – период анализа в днях (целое число)
  • quartiles_count – количество квантилей (целое число, обычно 5)
  • r_weights – веса для R-критерия (массив вещественных чисел)
  • f_weights – веса для F-критерия (массив вещественных чисел)
  • m_weights – веса для M-критерия (массив вещественных чисел)
  • created_date – дата создания конфигурации (дата)

Взаимосвязи между сущностями:

  • Один Клиент может иметь множество Транзакций (1:N)
  • Одна Транзакция принадлежит одному Клиенту (N:1)
  • Один Клиент может иметь множество RFM-оценок (разные периоды анализа) (1:N)
  • Одна RFM-оценка принадлежит одному Клиенту (N:1)
  • Один Сегмент включает множество Клиентов (1:N)
  • Один Клиент принадлежит одному Сегменту в рамках одного анализа (N:1)
  • Одна Конфигурация анализа используется для расчета множества RFM-оценок (1:N)
  • Множество RFM-оценок могут быть рассчитаны с использованием одной Конфигурации (N:1)

5. Бизнес-процессы и правила

5.1. Основные бизнес-процессы

Процесс 1: Импорт данных о клиентах

Участники: Маркетолог, Аналитик данных

Описание сценария (как есть):

  1. Пользователь выбирает файл с данными (CSV, Excel)
  2. Система проверяет формат файла и структуру данных
  3. Если формат некорректен – выводится сообщение об ошибке
  4. Если формат корректен – система загружает данные
  5. Система выполняет валидацию данных (проверка на дубликаты, пустые значения)
  6. Система отображает статистику загруженных данных
  7. Пользователь подтверждает импорт данных

Входные данные: Файл с данными о клиентах и транзакциях

Выходные данные: Загруженные и валидированные данные в системе

Процесс 2: Расчет RFM-метрик

Участники: Аналитик данных, Маркетолог

Описание сценария (как есть):

  1. Пользователь выбирает период анализа
  2. Пользователь выбирает или настраивает параметры RFM-анализа (количество квантилей)
  3. Система фильтрует транзакции по выбранному периоду
  4. Система рассчитывает Recency для каждого клиента (дни с последней покупки)
  5. Система рассчитывает Frequency для каждого клиента (количество покупок)
  6. Система рассчитывает Monetary для каждого клиента (сумма покупок)
  7. Система присваивает R-оценки на основе квантилей (меньшее значение = higher score)
  8. Система присваивает F-оценки на основе квантилей (большее значение = higher score)
  9. Система присваивает M-оценки на основе квантилей (большее значение = higher score)
  10. Система формирует RFM-сегмент для каждого клиента
  11. Система отображает результаты анализа

Входные данные: Загруженные данные о клиентах и транзакциях, параметры анализа

Выходные данные: RFM-оценки для всех клиентов, сегментация

Процесс 3: Визуализация результатов анализа

Участники: Маркетолог, Аналитик данных, Руководитель отдела продаж

Описание сценария (как есть):

  1. Пользователь выбирает тип визуализации (график распределения, тепловая карта, таблица)
  2. Система генерирует выбранную визуализацию на основе RFM-данных
  3. Пользователь может фильтровать данные по сегментам
  4. Пользователь может интерактивно исследовать данные (наведение, клик)
  5. Система обновляет визуализацию при изменении фильтров

Входные данные: Рассчитанные RFM-оценки и сегменты

Выходные данные: Интерактивные графики и диаграммы

Процесс 4: Экспорт результатов

Участники: Маркетолог, Аналитик данных

Описание сценария (как есть):

  1. Пользователь выбирает данные для экспорта (сегменты, отдельные клиенты)
  2. Пользователь выбирает формат экспорта (CSV, Excel, PDF)
  3. Система формирует файл в выбранном формате
  4. Система предлагает скачать файл

Входные данные: RFM-оценки, сегменты, статистика

Выходные данные: Файл в выбранном формате

5.2. Бизнес-правила

  • Правило 1: Для RFM-анализа могут быть использованы только клиенты, совершившие минимум одну покупку за выбранный период.
  • Правило 2: R-оценка рассчитывается по инверсному принципу: чем меньше дней прошло с последней покупки, тем выше оценка (5 – самая активная, 1 – наименее активная).
  • Правило 3: F-оценка и M-оценка рассчитываются по прямому принципу: чем больше частота покупок и сумма, тем выше оценка (5 – самые ценные, 1 – наименее ценные).
  • Правило 4: Количество квантилей для оценки должно быть от 3 до 10 (рекомендуется 5).
  • Правило 5: Период анализа должен быть не менее 30 дней и не более 5 лет.
  • Правило 6: При импорте данных дубликаты по client_id должны быть обработаны (объединены или удалены с предупреждением).
  • Правило 7: Значения суммы покупки (amount) должны быть положительными числами.
  • Правило 8: Дата транзакции не может быть больше текущей даты.

5.4. Процедуры принятия решений

Точка принятия решения Условие Действие
Валидация файла при импорте ЕСЛИ формат файла не поддерживается ТО вывести сообщение об ошибке и запросить другой файл
Валидация файла при импорте ЕСЛИ формат файла поддерживается ТО продолжить загрузку данных
Обработка дубликатов клиентов ЕСЛИ обнаружены дубликаты по client_id ТО предложить пользователю выбрать стратегию: объединить или удалить
Проверка данных для анализа ЕСЛИ количество транзакций < 10 ТО вывести предупреждение о недостаточности данных для анализа
Проверка данных для анализа ЕСЛИ количество транзакций >= 10 ТО разрешить выполнение RFM-анализа
Выбор типа визуализации ЕСЛИ выбран тип "Тепловая карта" ТО отобразить матрицу RFM-сегментов с цветовой кодировкой
Выбор типа визуализации ЕСЛИ выбран тип "Распределение по сегментам" ТО отобразить столбчатую диаграмму количества клиентов по сегментам
Фильтрация по сегменту ЕСЛИ пользователь выбрал конкретный сегмент ТО обновить все визуализации с данными только этого сегмента
Экспорт данных ЕСЛИ выбран формат PDF ТО сгенерировать отчет с графиками и таблицами
Экспорт данных ЕСЛИ выбран формат CSV/Excel ТО экспортировать только табличные данные
