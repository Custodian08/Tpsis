ПЛАН РАЗРАБОТКИ ПРОГРАММНОГО СРЕДСТВА

1. Анализ требований и выбор технологического стека

Обязательные требования к проекту:

  • Распределенная архитектура: сервер (REST API, JSON) + клиент (отображение данных)
  • Модель данных с нормализацией до 3НФ (если реляционная)
  • Функции авторизации и регистрации пользователей
  • Пользовательский интерфейс на русском языке
  • Соблюдение Code Convention
  • Работа на Windows 8+ без использования IDE
  • Актуальные версии фреймворков (2026 год)
  • Защита данных: шифрование, резервное копирование, хеширование паролей
  • Документация: руководство по установке и руководство пользователя

Предлагаемый технологический стек (Node.js + TypeScript):

Серверная часть (Backend):

  • Язык программирования: TypeScript 5.0+ (мультипарадигменный, транслируется в JavaScript)
  • Среда выполнения: Node.js 20+ (LTS версия)
  • Фреймворк: NestJS 10.0+ (современный архитектурный фреймворк для REST API) или Express.js 4.18+
  • База данных: PostgreSQL 16+ (реляционная СУБД)
  • ORM: TypeORM 0.3+ или Prisma 5.0+ (работа с базой данных)
  • Аутентификация: passport.js + JWT (JSON Web Tokens) + bcrypt/argon2 для хеширования паролей
  • Валидация данных: class-validator + class-transformer
  • Миграции базы данных: TypeORM Migrations или Prisma Migrate
  • Конфигурация: @nestjs/config

Клиентская часть (Frontend):

  • Язык программирования: TypeScript 5.0+
  • Фреймворк: React 18+ (или Vue.js 3.4+)
  • Сборщик: Vite 5.0+
  • HTTP-клиент: Axios
  • Визуализация данных: Recharts или Chart.js 4+
  • UI-библиотека: Material-UI (MUI) 5+ или Ant Design 5+
  • Управление состоянием: Redux Toolkit или Zustand
  • Маршрутизация: React Router 6+ или Vue Router 4+

Инструменты разработки:

  • Система контроля версий: Git
  • Менеджер пакетов: npm 10+ или yarn 1.22+ или pnpm 8+
  • Линтер и форматтер: ESLint + Prettier
  • Тестирование: Jest (backend и frontend), Supertest (API тестирование)
  • Упаковка в .exe: pkg или nexe (для Node.js приложения)
  • Docker (опционально) для контейнеризации

Этап 3: Разработка серверной части (Backend)

Задачи:

  1. Настройка проекта FastAPI
  2. Настройка подключения к PostgreSQL
  3. Реализация моделей TypeORM/Prisma (ORM)
  4. Создание миграций базы данных (TypeORM Migrations/Prisma Migrate)
  5. Реализация системы аутентификации и авторизации:
    • Регистрация пользователей
    • Вход в систему (JWT токены)
    • Обновление токенов
    • Хеширование паролей (bcrypt)
  6. Реализация REST API эндпоинтов (NestJS модульная архитектура):
    • POST /api/auth/register - регистрация (AuthModule)
    • POST /api/auth/login - вход (AuthModule)
    • POST /api/auth/refresh - обновление токена (AuthModule)
    • POST /api/data/import - импорт данных (DataModule)
    • GET /api/clients - список клиентов (ClientsModule)
    • POST /api/rfm/analyze - выполнение RFM-анализа (RFMModule)
    • GET /api/rfm/results - результаты анализа (RFMModule)
    • GET /api/segments - список сегментов (SegmentsModule)
    • GET /api/export/{format} - экспорт данных (ExportModule)
  7. Реализация бизнес-логики RFM-анализа:
    • Расчет Recency, Frequency, Monetary
    • Квантильное ранжирование
    • Сегментация клиентов
  8. Реализация защиты данных:
    • Шифрование передаваемых данных (HTTPS)
    • Хеширование паролей
    • Резервное копирование базы данных
  9. Написание unit-тестов для backend

Результат:

5. Механизмы обеспечения информационной безопасности

Защита передаваемых данных:

  • Использование HTTPS протокола для взаимодействия клиент-сервер
  • Валидация всех входных данных на сервере
  • Использование CORS для защиты от CSRF-атак
  • Rate limiting для защиты от DDoS-атак

Защита хранимых данных:

  • Хеширование паролей с использованием bcrypt (salt rounds: 12)
  • Шифрование чувствительных данных в базе данных (при необходимости)
  • Регулярное резервное копирование базы данных
  • Использование параметризованных запросов для защиты от SQL-инъекций

Аутентификация и авторизация:

  • Использование JWT токенов для аутентификации
  • Хранение токенов в httpOnly cookies
  • Реализация разграничения прав доступа (RBAC)
  • Истечение срока действия токенов (access token: 15 мин, refresh token: 7 дней)

6. Соответствие Code Convention

TypeScript (Backend + Frontend):

  • Соблюдение ESLint правил (конфигурация Airbnb или Google)
  • Использование Prettier для форматирования кода
  • Использование strict mode TypeScript (strict: true в tsconfig.json)
  • Использование type annotations для всех функций и переменных
  • Docstrings в формате JSDoc или TSDoc
  • Максимальная длина строки: 100 символов
  • Именование: camelCase для переменных и функций, PascalCase для классов/компонентов/интерфейсов
  • Использование интерфейсов для описания типов объектов
  • Использование enum для константных значений
  • Асинхронный код: async/await вместо Promises

Дополнительные соглашения для NestJS (Backend):

  • Модульная архитектура: разделение на модули (AuthModule, ClientsModule, RFMModule и т.д.)
  • Использование декораторов (@Controller, @Get, @Post, @Body и т.д.)
  • Dependency Injection через конструктор
  • DTO классы с валидацией через class-validator
  • Исключения через встроенные HttpException

Дополнительные соглашения для React/Vue (Frontend):

  • Функциональные компоненты с Hooks (React) или Composition API (Vue)
  • Разделение на компоненты: умные (smart) и презентационные (dumb)
  • Использование TypeScript пропсов (Props interface)
  • Управление состоянием через Redux Toolkit или Zustand
  • CSS Modules или styled-components для стилизации

Выводы

Разработанный план охватывает все этапы создания программного средства для RFM-анализа клиентской базы в соответствии с обязательными требованиями к курсовому проекту. Предложенный технологический стек включает современные фреймворки и библиотеки актуальных версий (2026 год): Node.js 20+ и TypeScript 5.0+ для backend и frontend, NestJS 10.0+ для REST API, React 18+ или Vue.js 3.4+ для клиентской части, PostgreSQL 16+ для базы данных.

Архитектура системы соответствует требованию распределенной природы: серверная часть на NestJS реализует REST API с передачей данных в формате JSON, клиентская часть на React/Vue выполняет только отображение полученных данных. Реализованы функции авторизации и регистрации пользователей с использованием JWT токенов и хеширования паролей (bcrypt/argon2).

TypeScript является мультипарадигменным языком, поддерживающим объектно-ориентированный, функциональный и императивный стили программирования, что соответствует требованию к выбору языка. Использование единого языка (TypeScript) на всем стеке упрощает разработку и сопровождение проекта.

Пользовательский интерфейс будет полностью на русском языке (за исключением названий классов, переменных, методов и атрибутов). Код будет соответствовать Code Convention (ESLint + Prettier для TypeScript). Система будет работать на Windows 8+ без использования интегрированных средств разработки. Backend часть может быть упакована в исполняемый файл .exe с помощью pkg или nexe.

Предусмотрены механизмы защиты данных: шифрование передаваемых данных (HTTPS), хеширование паролей (bcrypt/argon2), резервное копирование базы данных. Будет оформлена необходимая документация: руководство по установке и руководство пользователя.
